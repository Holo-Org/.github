# Triage labels

The skills speak in terms of five canonical triage roles. This file maps them to
the labels this organisation uses. Quote them: each contains a space and a
colon.

| Role | Label here | Meaning |
|---|---|---|
| `needs-triage` | `acting: maintainer` | Needs classifying or deciding before anyone can start. |
| `needs-info` | `acting: reporter` | Waiting on whoever filed it for something nobody else knows. |
| `ready-for-agent` | `acting: agent` | Fully specified; a fresh session can take it as written. |
| `ready-for-human` | `acting: human` | Needs a person: implementation, design, or judgement an agent should not make. |
| `wontfix` | *(no label)* | Close with `--reason 'not planned'`. The board shows it as `Cancelled`. |

```bash
gh issue edit 12 --repo Holo-Org/R-Type --add-label 'acting: agent'
```

## Rules

- **Exactly one on every open issue, and none on a closed one.** If an issue
  would carry two, say so and ask rather than guessing.
- Set it to what is true **after** your turn: handing an issue back to a human
  means `acting: human`, not leaving `acting: agent` on it.
- It is the availability query for the whole fleet, so a wrong one is either
  work nobody picks up or work two agents pick up at once.
- There is no `in-progress` value — being assigned says that, and the board
  derives `In Progress` from it. There is no `blocked` value either; use native
  issue dependencies.
- Every triage comment opens with `> *This was generated by AI during triage.*`

The other namespaces — `release:`, `component:`, `external:` — are described in
[../labels.md](../labels.md) and are not yours to set.
